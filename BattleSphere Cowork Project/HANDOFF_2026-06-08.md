# BattleSphere – Session Handoff (2026-06-08)

## Project overview
BattleSphere is a Next.js (App Router) web app for running map-based wargaming campaigns. Stack: React 19, Supabase (Postgres + RLS + Storage). Live on Vercel at https://www.battlesphere.cc. GitHub: https://github.com/B-Gruenwald/BattleSphere.

## File access — do this first
The source code is NOT in the default workspace folder. At the start of every session you must request access to the source directory:

```
request_cowork_directory: ~/Desktop/BattleSphere
```

This mounts to `/sessions/<session-id>/mnt/BattleSphere`. All code edits go here.
The "BattleSphere Cowork Project" folder (SQL migrations, handoffs) is a separate mount — already available at `/sessions/<session-id>/mnt/BattleSphere Cowork Project`.

## Autonomous git push — how to do it
```bash
cd /sessions/<session-id>/mnt/BattleSphere
git add <files>
git commit -m "..."
git push
```
If commit fails with `HEAD.lock` error: call `mcp__cowork__allow_cowork_file_delete` on the lock path, then `rm -f .git/HEAD.lock`, then retry.
Vercel auto-deploys on every push to `main`.

## Key technical rules
- All files use `.js` — never `.tsx` or TypeScript
- `'use client'` required for any component with event handlers or useState
- Server components (`page.js`) use `createClient` from `@/lib/supabase/server`
- Client components use `createClient` from `@/lib/supabase/client`
- Admin operations (cross-user data) use `createAdminClient` from `@/lib/supabase/admin`
- Page.js files are server components — never add event handlers directly in them; extract to a client component
- Benjamin is non-technical — keep explanations clear and jargon-free
- Supabase newly-added columns return `undefined` (not null) — always use `== null` (loose equality)
- All inputs must use `fontSize: '1rem'` to prevent iOS zoom-jump

## Built this session (2026-06-08)

### Extended Public Profile ✓
**DB migration:** `migration_profile_extended.sql` (run ✓)
New columns on `profiles`:
- `bio TEXT` — personal introduction (max 500 chars)
- `discord_handle TEXT`
- `game_systems TEXT[]` — array of selected game systems (multi-select on profile)
- `hobby_tags TEXT[]` — array of selected hobby focus tags
- `social_links JSONB` — `{ website: "...", instagram: "..." }`
- `banner_image_url TEXT` — Cloudinary URL
- `profile_visibility TEXT DEFAULT 'public'` — `'public'` | `'members'` | `'allies'`

`profile_visibility` replaces the old boolean `profile_public`:
- `public` → anyone including logged-out visitors
- `members` → any registered BattleSphere user
- `allies` → only users who share a campaign or league with this user (checked via `campaign_members` join)

**Modified/new files:**
- `app/profile/ProfileSettingsForm.js` — full rewrite; adds banner upload, bio, Discord, hobby links, game systems checkboxes, hobby focus tags, 3-option visibility toggle
- `app/players/[username]/page.js` — displays all new fields; visibility gate; imports `ProfileActions`
- `app/players/[username]/ProfileActions.js` — NEW; client component with "Edit Profile" (own profile only) + "Share" (copy link) buttons

**Profile page layout order:**
1. Banner image (full-width, 200px)
2. Username / rank / XP / member since + Edit/Share buttons
3. Bio (gold left-border block)
4. Game systems (plain bordered badges)
5. Hobby focus tags (gold bordered badges)
6. Discord + social links (icon chips; website/Instagram show actual domain)
7. Army Portfolios grid (faction + game system shown in gold)
8. Stats row (W/D/L, Armies, Campaigns)
9. Campaigns list
10. Recent Battles
11. Achievements
