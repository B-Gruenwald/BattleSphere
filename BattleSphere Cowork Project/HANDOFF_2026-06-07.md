# BattleSphere – Session Handoff (2026-06-07)

## Project overview
BattleSphere is a Next.js (App Router) web app for running map-based Warhammer 40K campaigns. Stack: React 19, Supabase (Postgres + RLS + Storage). Live on Vercel at https://battle-sphere-topaz.vercel.app. GitHub: https://github.com/B-Gruenwald/BattleSphere.

## File access — do this first
The source code is NOT in the default workspace folder. At the start of every session you must request access to the source directory:

```
request_cowork_directory: ~/Desktop/BattleSphere
```

This mounts to `/sessions/<session-id>/mnt/BattleSphere`. All code edits go here.
The "BattleSphere Cowork Project" folder (SQL migrations, handoffs) is a separate mount — already available at `/sessions/<session-id>/mnt/BattleSphere Cowork Project`.

## Autonomous git push — how to do it
```bash
cd /sessions/<session-id>/mnt/BattleSphere
git add <files>
git commit -m "..."
git push
```
If commit fails with `HEAD.lock` error: call `mcp__cowork__allow_cowork_file_delete` on the lock path, then `rm -f .git/HEAD.lock`, then retry.
Vercel auto-deploys on every push to `main`.

## Key technical rules
- All files use `.js` — never `.tsx` or TypeScript
- `'use client'` required for any component with event handlers or useState
- Server components (`page.js`) use `createClient` from `@/lib/supabase/server`
- Client components use `createClient` from `@/lib/supabase/client`
- Admin operations (cross-user data) use `createAdminClient` from `@/lib/supabase/admin`
- Page.js files are server components — never add event handlers (onMouseEnter etc.) directly in them; extract to a client component instead
- Benjamin is non-technical — keep explanations clear and jargon-free

## Completed features (cumulative)

### Core platform
- Map-based narrative campaign system with territories, factions, battles, influence
- Influence modes: `standard` (Win +3/+1, Draw +2), `victory` (Win +1 only), `off` (manual)
- Territory cascade (event-gated): winning faction gains influence in connected territories
- XP system: `app/lib/xp.js` — `calcPlayerXP()` / `getXPRank()`, ranks Recruit → Legend
- League format campaigns (W/D/L points table instead of influence map)
- Crusade unit records (XP, kills, upgrades, scars per unit per campaign)
- Army portfolios with unit portraits and photo galleries
- Player profiles, standings, achievements

### Admin / organiser tools
- Admin page (`/c/[slug]/admin`) — General Settings + Campaign Digest only
- Join requests: inline on `/c/[slug]/players` via `InlineJoinRequests.js`
- Remove player: inline on players page via `RemovePlayerButton.js`
- Delete battle: inline on battles page via `DeleteBattleButton.js` (reverses influence + cascade)
- Manage Factions: `AdminFactionManager.js` in admin section

### Notifications
- In-app bell + inbox (`/inbox`) via `user_notifications` table
- Triggered on: battle logged (opponent notified), campaign joined, achievement awarded, campaign event goes live
- Email digest via `app/api/cron/campaign-digest/route.js` (Resend)
- No manual push UI yet — flagged as a future feature

### SEO
- `metadataBase` in `layout.js`
- Canonical URLs on all 7 public pages
- Battle report OG image (`opengraph-image.js`): full-bleed photo, gradient overlay, text zone right 265px

### Factions
- `factions` table has `description TEXT` and `image_url TEXT` columns
- `AdminFactionManager.js`: gold "▸ Edit Details" button per row, expandable panel with description textarea + cover image upload (bucket: `faction-images`, public)
- Faction detail page: cover image hero → description block (coloured left border) → faction name/header → record strip
- Campaign dashboard faction standings: 40×40 thumbnail (coloured border) + description snippet per row

### Sub-territory influence bleed
Event-gated toggle (was hardcoded ×0.5):
- `campaign_events.sub_territory_bleed BOOLEAN DEFAULT false`
- `EventForm.js`: toggle section below Territory Cascade
- `CampaignMap.js`: accepts `subTerritoryBleed` prop; ×0.5 aggregation only applies when true
- Campaign dashboard: derives `subTerritoryBleed` from active events, passes to CampaignMap
- Territory detail page: conditionally applies ×0.5 to influence bar and footnote

### Email / spam fixes
- SPF, DKIM, DMARC all confirmed correct on battlesphere.cc
- Digest subject line now uses first announcement title: `${first.title} — BattleSphere`

### Database indexes
First-ever index migration (`migration_indexes.sql`) — run 2026-06-06. Covers all 18 high-frequency tables.

### Campaign dashboard — About drawer + Discord invite (added this session)
- `CampaignAboutDrawer.js`: slide drawer (reuses `.bulletin-drawer` CSS classes) triggered by a small "ℹ About" button next to the campaign title. Shows campaign name, setting label, and full description. Only renders when description is set.
- `campaigns.discord_invite_url TEXT` column (migration: `migration_discord_invite.sql` — must be run)
- Admin settings: new Discord invite link field (separate from webhook URL) in the Discord Integration section
- Campaign dashboard header: "Join the conversation on Discord" line with blurple icon appears below title when `discord_invite_url` is set

### Username fixes (added this session)
- Discord OAuth stores usernames with `#0` suffix (e.g. `banquetthebarbarian#0`). The `#` breaks profile URLs as browsers treat it as a URL fragment.
- All profile URL builders now strip `#...` via `.replace(/#.*$/, '')` before encoding
- Profile lookup page (`/players/[username]/page.js`) queries with `.or()` for both clean and raw form
- DB migration `migration_strip_discord_discriminators.sql` run 2026-06-07: strips `#...` from all existing profile usernames via `split_part(username, '#', 1)`
- Admin users list: profile links now point to `/players/[username]` (not campaign-scoped), visible for any user with a username regardless of campaign membership
- `ProfileSettingsForm.js`: new Username section at top — users can change their username (3–30 chars, letters/numbers/`_`/`-`, uniqueness checked, warns old links will break)
